# Security and privacy

The harness binds no public service. Original offload HTTP clients accept only literal loopback addresses. Routing clients retain that default; explicitly configured `remote` or `hosted` deployments require HTTPS and exact hostname allowlists. Those deployments receive workload prompts. Clients use no environment proxy, do not follow redirects, have a wall-clock deadline and response limits, and never execute returned tools or code. Endpoint URLs cannot contain credentials. Set `api_key_env` to the name of a local environment variable; do not put a secret in JSON. Backend error bodies are omitted because they can echo prompts or keys.

Results store hashes and metrics by default, not generated text. `save_outputs=true` explicitly stores answers, which may contain prompt data. Configurations, paths, hardware observations, and timing metadata are still sensitive in some environments. Local `results/` is ignored by git. The optional report publisher exports selected sanitized records to tracked `docs/results/` through a reviewable PR. Workloads committed here are original synthetic text. Do not publish private prompts, tokens, model weights, or logs with credentials.

## Campaign workers and publication

SSH workers use noninteractive OpenSSH and a bounded JSON protocol. Configure trusted host aliases, matching harness revisions, mapped artifact paths and per-worker inference credentials. The coordinator does not transfer credentials in campaign payloads. Local worker subprocesses strip GitHub publication tokens. Remote worker accounts should not hold publication credentials.

Persistent reservations belong to an attempt, not a heartbeat timeout. A lost connection retains ownership until completion or reservation cleanup is confirmed. Never remove a reservation while an owned model process may still be running. Windows and WSL workers need a shared lock directory for the same physical host.

Reports omit known credential fields, endpoint/private paths and retained prompt/answer bodies by default. This filtering is not a general data-loss-prevention system; benchmark metadata may still be sensitive. Publication requires an explicit `pull-request` configuration or `--publish-pr`/`publish-results` invocation. The publisher checks its file inventory, hashes, size and repository origin, works in an isolated Git worktree, never force-pushes, and never merges. See [RESULTS.md](RESULTS.md) for raw retention and retries.

The optional setup scripts install explicitly selected platform recipes and can download a narrowly selected, revision-pinned model manifest after license acknowledgement. They use argument arrays rather than shell command strings, require exact source revisions/release asset hashes, and reject unsafe archive paths. The ordinary smoke runner never executes generated programs. Upstream LiveBench is a separate explicit execution lane described below. Pin backend dependencies and review their native/Python loaders. Hugging Face `trust_remote_code` is disabled in the Accelerate worker unless `reviewed_model_code=true`; offline mode is not a sandbox and local custom code still executes if enabled.

AirLLM's internal loaders are version-dependent. Its worker requires `reviewed_airllm_source=true` before loading. That flag is an attestation, not an automatic audit. Run experimental model loaders under a separate unprivileged account/container with access only to model files and a dedicated cache. Review legacy pickle-bearing weight formats before use; prefer safetensors/GGUF where the engine supports them. Native parsers can still have vulnerabilities.

Local workers omit common secret-bearing environment variables and set Hugging Face offline/telemetry controls. This is defense in depth, not complete environment sanitization or network isolation. Use OS-level egress controls for sensitive workloads. Maintain the earlier Strata restrictions: loopback binding, API authentication, no unreviewed MCP/vision input, and verified model/engine downloads.

Do not assume free/open-source software makes every model permissively licensed. The catalog records Apache/MIT and model-specific terms separately, including Meta, NVIDIA, Gemma 3, Grok 2, OpenMDW, and the inherited Qwen condition on Kimi-Dev. No claim of FIPS, FedRAMP, or other certification is made by this project.

## Setup and upstream LiveBench execution

Setup is authorized software execution, including compiler/package build hooks. Source/version pins and release checksums protect identity; they do not make dependencies trustworthy. Transitive Python dependencies and Docker base layers are captured, not fully hash-locked. Review them before use and run under an unprivileged account. No broad upstream installer or driver installation is invoked. Engine-specific `extra_args` and Strata prepared configuration are trusted operator input, not an interface for untrusted model output.

Regular LiveBench answer generation uses `--no-incremental-grading` so coding answers are not graded on the host. The dedicated grader has no network/capabilities, a read-only root and source/answer mount, only judgment-output mounts writable, process/CPU/RAM limits, and no Docker socket. The tag is resolved to a local image ID for the run. Managed server memory is released before grading. This is an isolation measure, not a proof against malicious generated code or score manipulation; use a disposable host for adversarial models.

`--allow-agentic-execution` enables the pinned upstream agent/build/test Docker pipeline and is a different trust boundary. It can build/fetch task environments and does not inherit the regular grader's restrictions. Review it separately and keep personal files, credentials and unrelated Docker workloads out of that environment. The local static Agentic Coding smoke proxy never executes agents. Upstream answer/judgment logs contain full text regardless of the smoke runner's output-retention flag. The run folder and Docker artifacts should be reviewed before sharing. See [LIVEBENCH.md](LIVEBENCH.md).
